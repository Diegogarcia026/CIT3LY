Decisiones del proyecto CIT3LY



Alcance acordado



CIT3LY será un sistema orientado a la gestión de citas y reservaciones. El objetivo principal es facilitar el registro, consulta y administración de las citas realizadas dentro del sistema.



Para esta primera etapa del proyecto, el equipo acuerda trabajar con las funciones principales necesarias para que el sistema pueda gestionar correctamente las reservaciones.



El alcance inicial contempla:



\- Registro de citas o reservaciones.

\- Consulta de las citas registradas.

\- Modificación de una cita cuando sea necesario.

\- Cancelación de citas o reservaciones.

\- Consulta de disponibilidad antes de realizar una reservación.

\- Registro de la información necesaria del usuario para gestionar su cita.



Por el momento, el proyecto se concentrará en estas funciones principales. Cualquier característica adicional deberá ser revisada y acordada por el equipo antes de incorporarse al sistema.



Criterios de revisión de la documentación



Como parte del rol de Tester, se establecen los siguientes criterios para verificar que la documentación del proyecto sea clara y coherente:



1\. La descripción general del sistema debe coincidir con los requisitos definidos por el equipo.

2\. Las funciones de citas y reservaciones deben describirse de la misma manera en todos los documentos.

3\. No deben existir requisitos que contradigan el alcance acordado del proyecto.

4\. Los términos utilizados para usuarios, citas, reservaciones y disponibilidad deben mantenerse consistentes.

5\. Cada requisito deberá ser comprensible y estar relacionado con alguna función del sistema.

6\. Antes de integrar cambios a la rama principal, se deberá revisar que no existan contradicciones entre los documentos.



Revisión antes de integración



Antes de integrar la documentación completa a la rama principal, se revisarán los archivos creados por los demás integrantes para comprobar que todos describan el mismo funcionamiento de CIT3LY.



Si se encuentra alguna diferencia entre la descripción, los requisitos y las decisiones del proyecto, el equipo deberá acordar cuál será la versión correcta antes de realizar la integración final.
